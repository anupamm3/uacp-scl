# Design Decisions

| ID  | Decision |
|-----|----------|
| D-1 | `<variable>` gets a required `name` attribute. `source` is a dotted path into runtime data. The body is an optional template wrapping `{{name}}`. |
| D-2 | A document has an implicit root. An optional `<scl version="1">…</scl>` wrapper is allowed. Mismatched tags raise a clear error with line and column. The blueprint's stray `</excel>` is a typo. |
| D-3 | MCP is a tool protocol, not a provider API. It is out of scope; it can be a future extension. |
| D-4 | Model IDs live only in `config/models.yaml` and environment variables, never in code. |
| D-5 | The UACP message from the blueprint is wrapped in a JSON-RPC 2.0 envelope as `params`. |
| D-6 | Generated code from Agent Beta runs only inside a sandbox (restricted subprocess with timeout). |
| D-7 | Contradiction resolution uses a documented scoring formula (Step 20) with tunable weights. |
| D-8 | Only free providers are used by default. The OpenAI-compatible adapter makes paid providers a config change. |
| D-9 | Whiteboard defaults to in-memory with an SQLite option. Redis is an optional backend. |
| D-10 | In the SCL `Output` AST node, `schema` is defined as `dict[str, Any] | None = None` with the Pydantic attribute shadowing warning suppressed, preserving direct property access (`output.schema`) over Pydantic's deprecated class method. |
| D-11 | SCL parser uses a dedicated raw-text scanning mode for `<output format="json_schema">` to permit unescaped JSON containing `<` and `>` up to the closing `</output>`. AST nodes support optional `store_spans` (default `False`), allowing clean round-trip equality `parse(format(parse(x))) == parse(x)`. |
| D-12 | SCL variable binding escapes `<` to `&lt;` and `>` to `&gt;` in runtime values to prevent prompt/XML injection breakouts, preserving valid JSON payloads while protecting AST structure. Dotted-path resolution raises `MissingVariableError` with fuzzy match candidates. |
| D-13 | Output schema normalization uses table-driven keyword stripping and transformation for `openai_strict` (adds `additionalProperties: false`, forces all properties into `required`, turns optional fields into nullable `anyOf` unions) and `gemini` (strips unsupported OpenAPI keywords) with verified idempotence. Output enforcement uses `Draft7Validator` and `invoke_with_repair` auto-appends validation errors for multi-turn repair attempts. |
| D-14 | Adapter foundation replaces the minimal enforcer protocol with the full `Adapter` ABC, `CompiledRequest`, and `LLMResult` models. `LLMResult` synchronizes `text` and `content` for complete backward compatibility. Sliding-window `QuotaGuard` tracks per-minute and daily requests from `config/models.yaml` with environment variable overrides and supports both sleep and raise modes. |
| D-15 | `GeminiAdapter` integrates the official `google-genai` SDK using `client.aio.models.generate_content`. API key is loaded strictly from `GEMINI_API_KEY` (never logged or printed). Compilation structures identity into `system_instruction`, SCL examples into alternating `user`/`assistant` (`model`) turns, data blocks and query into the final user turn, and normalizes `strict=True` JSON schemas with fallback to `json_mode`. Invocation wraps calls in `QuotaGuard`, `with_retry`, and timeouts, mapping SDK exceptions (`ClientError`/`APIError` 429 to `RateLimited`, 401/403 to `AuthError`, `MAX_TOKENS` to `TruncatedOutput`, safety blocks to `ModelRefusal`). |
| D-16 | `OpenAICompatAdapter` integrates the official `openai` SDK using `client.chat.completions.create` with configurable `base_url` and `api_key_env`, serving Groq, OpenRouter, and compatible endpoints. Environment loading is centralized in a shared `load_env()` helper in `registry.py` to avoid duplication. Configuration in `config/models.yaml` defines default provider settings and alias overrides. Compilation compiles identity into system message, examples into alternating user/assistant turns, data blocks and prompt into the final user turn, and dynamically selects output mode (`native_schema` with `openai_strict` normalization, `json_mode` with schema instructions, or `prompt_only`). Invocation is protected with `QuotaGuard`, timeouts, exponential backoff honoring `Retry-After`, and exception mapping (429 to `RateLimited`, 401/403 to `AuthError`, `finish_reason == "length"` to `TruncatedOutput`, content filters and refusals to `ModelRefusal`). |
| D-17 | Typer CLI exposes `scl` and `uacp` console scripts with Rich output formatting. `scl lint` prints diagnostics with source lines and carets, failing with exit code 1 on errors (and on warnings with `--strict`). `scl ast` renders AST trees or JSON. `scl compile` binds data and compiles provider requests offline, hiding API keys and truncating long string payloads. `scl run` wraps adapters with `TrackingAdapter` to measure token usage and repair attempts via `invoke_with_repair`, normalizing message types across repair turns. |
| D-18 | UACP message envelope implements Pydantic v2 models (`UACPMessage`, `Party`, `CircuitBreakerState`) with sortable timestamp-prefixed IDs and strict timezone-aware UTC datetime normalization. Message payloads are typed per intent with a helper validator. JSON-RPC 2.0 envelopes wrap UACP messages in `params` with method validation `uacp.<intent>` and enforce standard error codes (`-32700`, `-32600`, `-32601`, `-32602`, `-32603`) as well as protocol-reserved codes (`-32001` HopLimitExceeded, `-32002` CapabilityNotFound, `-32003` SchemaViolation, `-32004` QuotaExceeded, `-32005` SessionExpired). Schemas are auto-generated to `docs/schemas/`. |
| D-19 | Ephemeral Whiteboard implements async `WhiteboardBackend` ABC with in-memory (`InMemoryWhiteboardBackend`) and SQLite (`SqliteWhiteboardBackend` via `asyncio.to_thread`) default backends. State writes maintain an SHA-256 hash chain over canonical JSON snapshots of full state for out-of-band tamper detection (`verify_chain`). Concurrency uses optimistic locking (`VersionConflict`), session TTL expiry uses an injectable clock, and agent reviews generate multi-agent drift reports (`drift_report`). `WhiteboardClient` provides typed Pydantic v2 helpers (`write_model`, `read_model`), and whiteboard artifacts are treated as untrusted content during prompt construction. |
| D-20 | Capability discovery implements `Capability` (with `complexity_level`, `strengths`, and `max_input_chars`) and `AgentCard` (with `current_load` and `role`). `CapabilityRegistry` maintains liveness via heartbeat leases (`default_ttl=30s`). `find()` enforces `complexity_level >= required_complexity` and ranks candidates by strength match count, lowest current load, lowest cost hint, preferred engine match, and latency, returning structured ranking rationales (`RankedAgent`). Multi-agent task planning provides `suggest_split()` to assign subtasks or diagnose unassigned reasons without external AI calls. Method decorator `@capability` and `build_agent_card()` generate `AgentCard` manifests automatically from decorated agent classes and optional SCL specifications. Missing capabilities return JSON-RPC error code `-32002` (`CAPABILITY_NOT_FOUND`). |
| D-21 | Router and loop safety circuit breaker implement asynchronous `Router`, `CircuitBreaker`, and `InProcessTransport`. Recipient resolution accepts either explicit `agent_id` or capability name via `CapabilityRegistry.find()` with ranking rationales recorded into `trace_id` (agent ID takes precedence when both are provided). Loop and runaway prevention enforces authoritative Whiteboard hop counting (`incr_hop`) with strict anti-spoofing rejection when advisory message hop counts disagree. Tripping conditions (authoritative hop count exceeding `max_hops` defaulting to 5 from `UACP_MAX_HOPS`, cycle detection of identical `(sender, recipient, sha256_canonical_payload)` transmissions appearing 2 or more times, provider quota exhaustion hooks, or Whiteboard session expiry) write a `"session.halted"` event, refuse subsequent deliveries, and return reserved JSON-RPC error codes (`-32001`, `-32004`, `-32005`). |
| D-22 | Agent base class (`Agent`) unifies SCL contract binding, adapter invocation via `invoke_with_repair`, capability discovery, and Whiteboard tracing. An agent's role is defined solely by its SCL specification, while its abilities are centralized on an `AgentCard` constructed via `register(registry, router)`. Dynamic load tracking (`update_load`), heartbeat leases, and automatic Whiteboard audit events (`agent.llm_call`, `agent.message_handled`) track tokens, repairs, and message routing. Synthetic financial ledger generation (`make_ledger.py`) deterministically creates balanced double-entry transactions and seeds known anomalies (`rounding_drift`, `duplicate_id`, `sign_flip`, `missing_counterpart`) paired with a deterministic baseline checker (`find_anomalies_baseline`) recovering 100% of anomalies. |
| D-23 | Agent Alpha (`AlphaResearchAgent`) integrates forensic financial audit SCL contracts with batch chunking and free-tier protections. Tasks with ledgers are partitioned into chunks by batch (configurable `entries_per_batch`) and de-duplicated by `(batch, id)`, while tasks without ledgers execute directly against the SCL specification. Hard ceilings (`max_llm_calls`) return partial results with `status="incomplete"` without failing, and provider rate limits (`RateLimited`) trigger exponential backoff retry. Audit outputs validate against Pydantic `FindingsReport` and `Finding` models (with backward-compatible coercion of simple string lists), write to Whiteboard key `"findings.v1"`, and delegate downstream remediation to Agent Beta via UACP `task_delegation` messages through the Router. |
| D-24 | Agent Beta (`BetaExecutionAgent`) and execution sandbox implement safe automated remediation. The sandbox enforces defense-in-depth via AST static checks (restricting imports to safe standard modules, denying built-ins `eval`/`exec`/`compile`/`open`/`__import__`, blocking dunder escapes and process/network modules), subprocess isolation (`python -I`) with stripped secret-free environments, output caps (64KB), and timeouts (with POSIX resource limits on Linux/macOS). Beta reads findings dynamically from the task-specified Whiteboard key, treats all Whiteboard data as untrusted inputs, validates cryptographic chain integrity via `verify_chain` (refusing on tamper), executes generated code inside the sandbox, and verifies remediation with `find_anomalies_baseline`. On static check or runtime execution failure, an automated single-repair loop is triggered; if still failing, an honest failure report (`passed=False`) is recorded to `final_report.v1` without uncaught exceptions or infinite retries. |
| D-25 | End-to-end multi-agent execution runner (`uacp.runner`) unifies live tracing, metrics evaluation, record/replay, quota safety, and runaway loop demo. Rich live tracing wraps `WhiteboardBackend` (`TracingWhiteboardBackend`) and `Router` (`TracingRouter`) to render every message hop (sender, recipient, intent, message hop, authoritative whiteboard hop), whiteboard writes, and LLM call tokens/repairs in real time. The circuit breaker runaway demo (`uacp run loop-demo`) executes two scripted agents ping-ponging delegations, demonstrating safety by tripping at exactly hop 5 (`HOP_LIMIT_EXCEEDED`, `-32001`) and halting the session. Record/replay (`RecordManager`, `RecordingAdapter`, `ReplayAdapter`) captures SHA-256 canonical request hashes and raw replies (strictly zero API keys) for exact offline deterministic replay. The forensic challenge (`validation-challenge`) enforces quota safety warnings before live runs, calculates Alpha precision/recall against `ground_truth.json`, verifies Beta mitigation fraction using `find_anomalies_baseline`, validates `final_report.v1` against `FinalReport`, and exports full JSON metrics. |
